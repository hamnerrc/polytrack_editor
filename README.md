# PolyTrack Studio

A browser-based track builder that generates PolyTrack import codes. Open `index.html` in a browser — no build step or server required.

## Modes

- **KML Circuit** — convert a Google Earth path (KML) into a 1:1-scale circuit (1 block = 20 × 20 m), with optional real terrain elevation via open-elevation.com.
- **Shape Builder** — place lines, rectangles, cubes and hills block by block.
- **Pixel Art** — turn an image into a block mosaic, matched to the colours PolyTrack really shows, with optional dithering. Two targets: the **map preview** on a track's page (the game draws it with 5 colours: empty, base, checkpoint yellow, start blue, finish red) or the **in-game view** (16 colours: every flat block colour plus bare ground, measured per environment).

## Project layout

```
index.html        Page markup
css/styles.css    All styles (light/dark theme tokens at the top)
js/state.js       Shared constants (block IDs, ramp rotation table), app state, DOM helpers
js/ui.js          Theme, toast, status log, debug console, mode switching
js/geometry.js    3D Bresenham lines, haversine, RDP simplification, direction snapping
js/encoder.js     PolyTrack1 binary format + zlib/base-62 encoding, copy/download
js/kml.js         KML parsing, elevation lookup, road/ramp/checkpoint generation, preview canvas
js/shapes.js      Shape builder, ID test track, JSON export
js/hill.js        Hill inserter and its rotation diagram
js/pixel-palette.js  In-game block colours (generated by tests/polytrack/calibrate-colors.mjs)
js/pixel.js       Colour matching, dithering and pixel-art track generation
js/main.js        Startup wiring
```

Scripts are plain (non-module) scripts loaded in order, so the page also works when opened directly from `file://`.

## Testing against the real game

`tests/polytrack/` drives the editor and the real PolyTrack game together in headless Chrome:
every scenario is generated through the editor's UI, decoded by the game's own importer, checked
against the game's own part footprints (overlaps, gaps, reachability, orientation) and then
actually driven by an autopilot until the game registers a finish. Pixel art is compared pixel-for-pixel with the map preview the game draws, and photographed
from above in the game for the in-game target.

```
cd tests/polytrack
npm install
npm test                      # all scenarios (about 20 minutes - tracks are driven in real time)
node run.mjs kml              # only scenarios whose name contains "kml"
node calibrate-colors.mjs     # re-measure block colours and regenerate js/pixel-palette.js
```

Screenshots, track codes and `results.json` are written to `tests/polytrack/out/`.
Needs Google Chrome (set `CHROME_PATH` if it is not in the default location) and internet access to load the game.
